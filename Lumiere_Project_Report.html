1. Abstract & Executive Summary

The Lumière Cinema Booking System is a full-stack, modular web application developed as part of the Object-Oriented Programming (OOP) curriculum in Java. The project solves a traditional software engineering challenge: transitioning bulky, platform-dependent desktop user interfaces (Java Swing) into an elegant, high-performance web client without abandoning pure Java as the primary backend engine.

The backend leverages the standard Java HTTP Server (com.sun.net.httpserver.HttpServer) with zero third-party framework overhead. The client presents a modern, responsive single-page cinema booking experience featuring interactive seat matrices, live tax calculations, customer verification, and transactional booking management.

3. Object-Oriented Programming (OOP) Implementation

The system serves as an exemplary demonstration of core OOP principles:

A. Encapsulation & Robust Validation

All domain entity fields (movie title, seat count, price, phone) are strictly declared private. Data mutators implement defensive boundary validation:

  • Customer Phone Number: Enforced using regular expressions (^\d{10}$) to guarantee exactly 10 numeric digits.
  • Ticket Seat Arrays: Defensive cloning (seats.clone()) ensures external callers cannot mutate internal state.

B. Object Composition

The project models realistic business entities through composition (HAS-A relationship) rather than fragile inheritance:

  • Ticket HAS-A Movie
  • Ticket HAS-A Customer

C. Inheritance & Polymorphism

The PremiumTicket class extends the base Ticket class (IS-A relationship), representing luxury recliner seating:

public class PremiumTicket extends Ticket { public static final double RECLINER_FEE = 100.0; @Override public double calculateBill() { double reclinerTotal = getSeats().length * RECLINER_FEE; return super.calculateBill() + (reclinerTotal * gstMultiplier()); } }

The central BookingStore calculates financial revenue polymorphically by invoking ticket.calculateBill() without needing to inspect runtime object types.

D. Static Members & Centralized Configuration

Class-level static variables are utilized for theater-wide properties such as THEATRE_NAME, GST_PERCENT (18.0%), CONVENIENCE_FEE (Rs. 10.00), and a global atomic booking counter.

4. Backend & Concurrency Architecture

Embedded HTTP Web Server

Developed by Kabir Ubale in App.java, the server exposes lightweight JSON REST endpoints:

  • GET /api/movies: Delivers active movie catalog with metadata and poster paths.
  • GET /api/booked-seats?movie=...&show=...: Returns array of occupied seats for the selected showtime.
  • POST /api/book: Processes atomic ticket reservation and validation.
  • POST /api/cancel: Releases seats and removes booking by ID.
  • GET /api/summary: Aggregates real-time KPIs (Total Revenue, Active Seats, Booking Counts).

Thread-Safe Seat Collision Prevention

All state mutations in BookingStore.java utilize method-level synchronization (synchronized) to prevent race conditions when multiple users attempt to reserve adjacent seats concurrently.
